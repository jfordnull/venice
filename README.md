# Venice

## Description
Venice is a real-time strategy game set on the high seas of Italy or something.

## Contributing

### Development Guidelines
1. All reviews should confirm that pull requests follow these guidelines.
2. Avoid editing existing scenes whenever possible.
    - Instead, create prefabs, sample scenes, etc.
    - If the current issue adds items that need to be added to an existing scene, **create a new [sub-]issue/branch/PR to do so.**
    - If the purpose of the current issue is to edit an existing scene, mark the issue/PR with the **"integration" label.**
3. Document less straightforward code using comments within the file or a README file in the directory of the file (feel free to add these as you see fit).
4. When creating and working issues, **break up the issue into the smallest functioning parts**. Consider using sub-issues to coordinate this.
5. When claiming an issue and creating a branch, use the **"Create branch"** feature on the issue under the Development label to the right. Feel free to shorten the length of the branch name, but **please keep the number at the beginning** so it's easier to tell what issue it is linked to.
6. When you create a PR, feel free to **assign a reviewer** based on who you think might be best fit to analyze the changes.
7. Only review PRs if you are **willing to read through** all of the changes.
    - If you are assigned to a review but don't feel capable or willing to review it, **assign it to someone else**.
8. When merging a PR into main, use the **"squash and merge"** option.
    - The issue assignee is responsible for merging the PR once it is approved.
9. Sometimes issues need to be closed without changing anything (non-reproduceable bug, feature not desired, duplicate, etc.). In this case, **close as not planned or as duplicate** instead of the default close action.
